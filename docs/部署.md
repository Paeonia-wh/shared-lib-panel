# 部署说明（写给 AI 会话看的）

> **这份文档的读者不是人，是"帮用户部署这个面板的 AI 会话"。**
> 用户会把仓库丢给你、说"给我装上"，你照着下面做完即可。
> 每一步都写了**怎么验证**，别跳过验证就说"装好了"。

---

## 0. 先搞清楚这是什么、不是什么

```
这个仓库 = 一个桌面悬浮球面板（Tauri 2 + Rust）
它自己 **不产生数据**，它读的是【另一个仓库】的项目库
```

所以：**先有库，再有面板。** 面板单独跑起来只会是空的。

```
┌─────────────┐        ┌──────────────────┐        ┌──────────────┐
│  AI 会话    │──MCP──▶│  codex-memory    │◀──SQL──│   面板       │
│ （干活的人）│        │  （项目库/真相源）│        │ （显示的人） │
└─────────────┘        └──────────────────┘        └──────────────┘
                              ▲
                          PostgreSQL
```

**如果用户只想要面板**，告诉他：**没有库的话面板是空的，得先装库。**

## 1. 检查清单（按顺序做，别跳）

| # | 步骤 | 怎么验证 |
|---|---|---|
| 1 | 装好后端 `codex-memory` | `.\scripts\start-memoryd-silent.ps1` 能起来 |
| 2 | 确认 PostgreSQL 在跑 | 见下面「第 2 步」的验证命令 |
| 3 | 装面板（`releases` 里下载 exe，**不用编译**） | 双击能出现小球 |
| 4 | 面板能连上库 | 点开面板**能看到项目**（不是空的） |
| 5 | 共享工具能用（可选） | 见「第 4 步」 |

## 2. 后端：codex-memory

```powershell
git clone https://github.com/Paeonia-wh/codex-memory.git D:\codex-memory\repo
cd D:\codex-memory\repo
.\scripts\bootstrap.ps1 -Minimal      # 精简档 ~2GB；要语义检索/文档解析再去掉 -Minimal
.\scripts\start-memoryd-silent.ps1    # 起 PostgreSQL + memoryd
```

**装到别的盘/别的目录**都可以，但**后面面板要用到**：

| 用到的 | 默认值 |
|---|---|
| 库的根目录 | `D:\codex-memory` |
| Python 解释器 | `<根目录>\runtime\venv\Scripts\python.exe` |
| 源码目录 | `<根目录>\repo\src` |

**根目录换了** → 面板侧要设 `CODEX_MEMORY_HOME`（见第 3 步）。

**验证 PostgreSQL 真的在跑**：

```powershell
# 应该能看到 55440 在监听
Get-NetTCPConnection -LocalPort 55440 -State Listen -ErrorAction SilentlyContinue
```

## 3. 面板

**优先用发布的 exe**（GitHub → Releases → `shared-lib-panel.exe`）——
**不需要 Rust，也不需要 VS Build Tools**（那两个加起来 6.8GB）。
只有用户要**改面板源码**时才需要编译。

### 面板的连接参数（**这是最容易出错的地方**）

面板默认连 `127.0.0.1:55440`。**如果用户的库不在这个地址/端口，面板会是一片空**。
用环境变量改（**不需要改代码、不需要重新编译**）：

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `PANEL_PG_DSN` | 无 | **整串优先**。给了它，下面几个都忽略。例：`host=127.0.0.1 port=55440 user=codex_memory dbname=codex_memory` |
| `PANEL_PG_HOST` | `127.0.0.1` | 数据库主机 |
| `PANEL_PG_PORT` | `55440` | 数据库端口 |
| `PANEL_PG_USER` | `codex_memory` | 用户名 |
| `PANEL_PG_DB` | `codex_memory` | 库名 |
| `PANEL_PG_PASSWORD` | 无 | 有密码时才要 |
| `CODEX_MEMORY_HOME` | `D:\codex-memory` | 库的根目录（token 那步要用） |
| `PANEL_PYTHON` | `<HOME>\runtime\venv\Scripts\python.exe` | 面板读服务 token 用的解释器 |
| `PANEL_REPO_SRC` | `<HOME>\repo\src` | codex-memory 的 src 目录 |
| `PANEL_EXPORT_DIR` | `文档\共享项目库-导出` | 导出 PDF 落到哪 |

**看门狗**（面板会盯着 PostgreSQL/memoryd，掉了自动拉回来）—— 一般不用动，
除非用户嫌它太敏感/太迟钝：

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `PANEL_WATCHDOG_CHECK_SECS` | `60` | 多久检查一次（秒） |
| `PANEL_WATCHDOG_FAILS` | `3` | **连续失败几次**才动手救（防止一次抖动就重启） |
| `PANEL_WATCHDOG_COOLDOWN_SECS` | `30` | 救完等多久再检查（防止反复重启打架） |

**设环境变量（当前用户永久生效）**：

```powershell
[Environment]::SetEnvironmentVariable('PANEL_PG_PORT', '55441', 'User')
# 设完要重启面板才生效
```

### 验证面板连上了

```powershell
# 看面板自己的调试日志（和 exe 同目录）
Get-Content "<面板目录>\debug.log" -Tail 20
```

**连不上时日志长这样**（我特意让它带上实际地址，方便定位）：

```
loadProjects 失败: PG连接失败（codex_memory@127.0.0.1:55441/codex_memory）: error connecting to ...
```

**看到这行 = 端口/主机不对**，按上表改环境变量。

## 4. 共享工具（`call_shared_tool`）能不能用

面板有一部分功能要**读服务 token**（它跑一个小 Python 命令拿 DPAPI 加密的 token）。
用到的就是上面的 `CODEX_MEMORY_HOME` / `PANEL_PYTHON` / `PANEL_REPO_SRC`。

**找不到 Python 时的报错**（也是特意写清楚的）：

```
找不到 Python：D:\codex-memory\runtime\venv\Scripts\python.exe
这是面板读服务 token 用的解释器。请设环境变量 PANEL_PYTHON 指向你的 venv\Scripts\python.exe
（或设 CODEX_MEMORY_HOME 指向库的根目录）。
```

**按它说的设 `PANEL_PYTHON` 即可。**

## 5. ★ 面板上那些「复制块」是怎么回事（**别搞错这个**）

面板上点任务卡可以复制一段中文指令，粘给任意 AI 会话，那个会话就能接手。

**那些块的内容里有几条指令，含义是这样的**：

| 块里让会话做的事 | 为什么 |
|---|---|
| 调 `project_overview` / `project_task_dispatch` / `project_context_pack` / `project_task_create` … | 这些是 **codex-memory 提供的 MCP 工具**。会话必须**已经接入**这套工具，否则调不到 |
| 「去读 `docs\xx.md`」 | **只是延伸阅读，不是必经步骤**。路径打不开就跳过 —— 块里已经写明了 |
| 「先别动手，先问用户」 | 有意设计的门槛：合同里没有可判定的验收判据时，**不许开工** |

### ⚠️ 所以有一件事必须确认：**用户的 AI 接入了这套 MCP 工具吗？**

**没接入的话**，块里的工具名调不到，会话会报错。这时你要做的是：

```
让用户按 codex-memory 的文档把 MCP 工具接进他的 AI（那一步在库那边的文档里）
```

**面板本身不负责接入 MCP** —— 它只负责"显示进度 + 生成那段指令"。

## 6. 常见故障对照

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 双击 exe 没反应 / 立刻退出 | 缺 WebView2 运行时 | Win10/11 通常自带；没有就去微软官网装（免费） |
| 面板打开**是空的** | ① 连不上库 ② 库里真的没项目 | 看 `debug.log`。有 `PG连接失败（…地址…）` → 按第 3 步改环境变量；没有报错 → 库里确实没数据，去库那边建项目 |
| 日志里有 `找不到 Python：…` | `PANEL_PYTHON` 没设或路径不对 | 按第 4 步设 |
| 导出 PDF 后找不到文件 | 落到了默认目录 | 在 `文档\共享项目库-导出\<项目>` 下；或用 `PANEL_EXPORT_DIR` 改到一个他熟悉的地方 |
| 会话照块做了但工具报"不存在" | 那个会话没接入 MCP 工具 | 见第 5 步 |
| 会话说"文档打不开" | 那只是延伸阅读 | **让它忽略，按块里其余内容继续** —— 块本身是自足的 |

## 7. 装完之后，告诉用户这几件事

```
① 面板在哪：桌面右上角那颗球，点开是项目列表
② 数据从哪来：不是面板产生的，是 AI 会话写进项目库的
③ 怎么用：让 AI 干活 → 活记进库 → 面板上看进度 → 换会话时点任务卡复制那段指令
④ 库的那份文档在 codex-memory 仓库的 docs\ 下（SETUP.md / 接手任务.md / 干活纪律.md…）
```

---

## 8. 给 AI 会话的几条纪律（**你自己也要守**）

```
· 别改面板代码去适配环境 —— 用环境变量。改代码会让用户下次更新时冲突
· 装完必须验证「点开面板能看到项目」，不能只说"装好了"
· 报错原文照贴给用户，别翻译成"配置有点问题"
· 用户说"没有库"时，先解释清楚面板是前端 —— 别硬装一个空壳给他
· 别为了让它"看起来能跑"去伪造数据
```
